# FOMO FLOW 使用说明书

版本：9.9.423

本文面向购买后第一次使用 FOMO FLOW 的用户，主线是 **Devin Local + BYOK**。建议先完成第一章到第四章，再按需要启用模型反代、协议中转和其他模块。

## 0. 先理解 FOMO FLOW

FOMO FLOW 是运行在本机的模型路由层。Devin 仍负责工作区、工具和对话界面，FOMO FLOW 负责把模型请求送到你配置的 Provider。

一次典型请求如下：

```text
Devin Local
    -> FOMO FLOW 本机控制面
    -> 模型 UID 路由
    -> Provider / 上游真实模型
    -> 协议适配、流式回传、用量记录
```

它不提供模型额度，也不会替你购买 Provider。你需要自备 API Key、Base URL、模型名和可用网络。

主要能力：

- 多 Provider、多模型和多备用渠道。
- OpenAI Chat、OpenAI Responses、Anthropic Messages、Gemini 兼容协议适配。
- 失败重试、渠道优先级、会话亲和、熔断和自动探活。
- Provider 用量、缓存命中和估算成本可见。
- 本地模型反代，给其他本地程序使用标准 SDK。
- 协议中转，把 Chat-only 渠道转换成 Responses、Anthropic 或 Gemini 入口。
- 自定义模型、思考强度、项目提示词、Agent HUD、Codex 热路由和文件变更审阅。

## 1. 安装

### 1.1 图形界面安装

1. 打开 Devin Local。
2. 进入扩展管理页面。
3. 点击更多操作，选择 **Install from VSIX**。
4. 选择本包中的 `fomo-flow-9.9.424.vsix`。
5. 安装完成后执行 **Reload Window**；如果扩展列表没有更新，完全退出并重新打开 Devin Local。

### 1.2 命令行安装（可选）

如果宿主提供命令行入口，可执行：

```powershell
devin-desktop --install-extension "D:\\FomoFlow\\fomo-flow-9.9.424.vsix" --force
```

macOS/Linux 使用宿主自身的 CLI 名称和路径。命令行名称因安装方式不同可能不同，图形界面安装更稳妥。

### 1.3 安装后检查

打开命令面板（通常是 `Ctrl+Shift+P` 或 `Cmd+Shift+P`），搜索：

```text
FOMO FLOW: Self Check
```

运行后，至少应能看到本机控制面存活、版本和当前监听端口。如果控制面尚未就绪，先 Reload Window 再检查。

## 2. Devin Local BYOK：第一次接通

### 2.1 打开渠道设置

运行命令：

```text
FOMO FLOW: Provider and Route Settings
```

或打开活动栏里的 **FOMO FLOW**，进入模型路由配置面板。

首次启动时，插件会在用户目录创建配置目录：

```text
macOS/Linux: ~/.fomo-flow/
Windows:     %USERPROFILE%\\.fomo-flow\\
```

核心渠道配置文件是：

```text
配置.json
```

没有配置文件时，插件会从内置无密钥模板创建一份。模板只用于展示字段，不包含任何可用账号。

### 2.2 添加 Provider

在“渠道配置”区域新增一个 Provider，填写：

| 字段 | 含义 | 填写建议 |
| --- | --- | --- |
| Provider 名称 | 本机配置中的唯一别名 | 用 `openai-main`、`deepseek-main` 这类稳定名称 |
| Base URL | 上游 API 根地址 | 填根地址，不要重复拼接完整请求路径 |
| Protocol | 上游协议 | `openai-chat`、`openai-responses`、`anthropic` 或 `gemini` |
| API Key | 上游凭据 | 只在买家自己的电脑填写 |
| Models | 真实模型名 | 以 Provider 实际接受的名称为准 |
| Completion Path | 补全路径 | OpenAI Chat 常见为 `/chat/completions`，Anthropic 常见为 `/v1/messages` |
| Stream Mode | 返回方式 | 支持流式时使用 `stream` |
| Extra Headers | 额外请求头 | 仅在 Provider 要求时填写，例如 Anthropic beta 头 |
| Pricing | 价格估算 | 可填写每 1K input/output token 的价格 |

建议先只接通一个 Provider，验证成功后再添加备用渠道。

### 2.3 推荐的最小配置

下面是结构示例，不能直接使用。把 `YOUR_...` 替换成买家自己的值：

```json
{
  "providers": {
    "openai-main": {
      "enabled": true,
      "apiKey": "YOUR_PROVIDER_API_KEY",
      "baseUrl": "https://provider.example/v1",
      "protocol": "openai-chat",
      "type": "openai-compatible",
      "completionPath": "/chat/completions",
      "streamMode": "stream",
      "models": ["YOUR_UPSTREAM_MODEL"]
    }
  },
  "daoRoutes": {
    "enabled": true,
    "routes": {}
  }
}
```

保存后点击“探活”或运行：

```text
FOMO FLOW: Self Check
```

探活失败时，优先检查 Base URL 是否多拼了一段路径、API Key 是否过期、模型名是否真实存在，以及系统代理是否能访问上游。

## 3. 把 Devin 模型 UID 路由到 BYOK

Provider 接通后，还需要告诉 FOMO FLOW：Devin 发来的哪个模型 UID 应该送到哪个上游模型。

### 3.1 在面板操作

1. 打开 **Provider and Route Settings**。
2. 进入“模型路由”区域。
3. 选择 Devin 的模型 UID。
4. 选择 Provider 和真实上游模型。
5. 选择协议和思考强度。
6. 如果有备用渠道，点击“加入优先队列”。
7. 保存后运行一次端到端测试。

模型 UID 是 Devin 发给路由层的标识，通常和 Provider 的真实模型名不同。不要把显示名称误当成 UID；以面板列出的 UID 为准。

### 3.2 配置文件方式

路由表位于 `daoRoutes.routes`。一个带备用渠道的示例：

```json
{
  "daoRoutes": {
    "enabled": true,
    "routes": {
      "YOUR_DEVIN_MODEL_UID": {
        "provider": "openai-main",
        "model": "YOUR_PRIMARY_MODEL",
        "protocol": "openai-chat",
        "maxOutputTokens": 16384,
        "reasoningLevel": "off",
        "autoFallback": true,
        "channelPriority": [
          {
            "provider": "openai-main",
            "model": "YOUR_PRIMARY_MODEL",
            "protocol": "openai-chat"
          },
          {
            "provider": "deepseek-main",
            "model": "YOUR_BACKUP_MODEL",
            "protocol": "openai-chat"
          }
        ]
      }
    }
  }
}
```

修改文件后可在面板点击“热重载”，通常不需要重启 Devin。若修改后状态异常，先运行官方直连恢复，再重新加载配置。

### 3.3 路由生效验证

按顺序检查：

1. `Provider and Route Settings` 中 Provider 显示为已启用。
2. 模型路由中能看到 UID、Provider、真实模型和协议。
3. 点击“全链路测试”返回成功。
4. 在 Devin 新建对话发送简单问题。
5. 在 FOMO FLOW Overview / Model Routing 面板查看最近请求、渠道和错误信息。

不要用旧对话判断首次路由是否成功。切换 Provider 或系统提示词后，建议新建一条 Devin 对话。

## 4. 自动故障转移和熔断

FOMO FLOW 不会无条件轮询所有渠道。它会结合渠道优先级、健康状态、延迟、成本信息、缓存亲和和任务适配进行选择。

### 4.1 失败分类

- `401`：通常视为鉴权失败，会快速熔断该 Provider。
- `403`：如果是余额、配额或权限问题，会进入较长冷却。
- `404`：通常表示模型或路径不正确。
- `408/425/429`：按 Retry-After 和退避策略处理。
- `5xx`、TLS 失败或网络断开：先累计 strike，达到阈值后熔断。

### 4.2 熔断后的行为

1. 当前渠道暂时从候选中移除。
2. 当前会话的渠道亲和被暂存，避免马上反复撞同一个故障。
3. 备用渠道按队列继续尝试。
4. 后台按间隔探活原来的 Provider。
5. 探活恢复后解除熔断，并尽可能恢复原会话亲和。

### 4.3 成本和预算

在 Provider 的 `pricing` 中填写：

```json
{
  "inPer1k": 0.003,
  "outPer1k": 0.015,
  "currency": "USD",
  "budgetLimit": 20
}
```

价格只用于本地估算、排序和告警，不会替你向 Provider 结算。没有配置价格时，路由层不会猜测价格。

## 5. 思考强度和自定义模型

### 5.1 思考强度

在路由或自定义模型中选择关闭、最小、低、中、高、超高、最大或自动。FOMO FLOW 会按上游协议转换：

- OpenAI Chat：使用兼容的 reasoning 参数。
- OpenAI Responses：使用 `reasoning.effort`。
- Anthropic：使用 thinking 类型和 budget tokens。
- Gemini：使用 thinking budget。

如果 Provider 不支持某个档位，面板会减少可选项；不要强行手写不受支持的参数。

### 5.2 自定义模型

运行：

```text
FOMO FLOW: Provider and Route Settings
```

在“自定义模型”区域填写：

- Devin 模型 UID。
- 显示名称。
- Provider 和上游真实模型。
- 上游协议。
- 思考能力和默认档位。
- 一个或多个有序渠道。

保存后，模型会同步到模型路由、模型反代和协议中转的选择列表。删除前如果仍被路由或中转档案引用，插件会提示引用关系。

## 6. 本地模型反代

模型反代用于让本地脚本、其他 IDE 或标准 SDK 复用已接通的模型。

### 6.1 开启

运行：

```text
FOMO FLOW: Local Model Gateway Toggle
```

或在设置中开启：

```text
dao.revproxy.enabled
```

反代配置保存在：

```text
~/.fomo-flow/revproxy.json
```

默认只允许本机访问。面板会显示当前 Base URL、API Key 和可反代模型。

### 6.2 支持的本地端点

端口由插件动态决定，以面板显示为准。常见端点：

```text
POST /v1/chat/completions
POST /v1/responses
POST /v1/messages
POST /v1beta/models/{model}:generateContent
POST /v1beta/models/{model}:streamGenerateContent?alt=sse
GET  /v1/models
```

OpenAI SDK 示例：

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:PORT/v1",
    api_key="YOUR_LOCAL_GATEWAY_KEY",
)

result = client.chat.completions.create(
    model="YOUR_PUBLIC_MODEL_ALIAS",
    messages=[{"role": "user", "content": "你好"}],
)
print(result.choices[0].message.content)
```

Anthropic 客户端使用 `/v1/messages`，Gemini 客户端使用对应的 `v1beta/models/...` 路径。面板里的“一键自测”会自动生成四种协议的请求样例。

### 6.3 访问安全

- `apiKey` 为空时，只允许本机回环请求。
- 设置 `apiKey` 后，本机和转发请求都必须带 Bearer、`x-api-key` 或 `x-goog-api-key`。
- 开启 `exposeLan` 或公网隧道前，必须设置强 API Key，并限制模型外接列表。
- 不要把反代地址和 Key 一起发布在截图或公开帖子里。

## 7. 协议中转站

协议中转用于把一个真实上游协议包装成另一个客户端需要的协议。

### 7.1 创建中转档案

在三模块配置面板进入“协议中转站”：

1. 选择“使用已有渠道”，或新建一个受 FOMO FLOW 管理的 Provider。
2. 填写真实模型和上游协议。
3. 选择允许的输出协议：OpenAI Chat、OpenAI Responses、Anthropic 或 Gemini。
4. 设置公开模型别名、最大输出 token 和思考档位。
5. 保存并同步。

档案保存在：

```text
~/.fomo-flow/protocol-bridges.json
```

API Key 仍来自 Provider 配置，不会复制到中转档案中。

### 7.2 验证中转

保存后展开“协议转换全链路测试”：

1. 选择档案和目标协议。
2. 点击“测试所选协议”，检查 HTTP 状态和响应结构。
3. 如需一次验证全部协议，点击“测试档案全部协议”。
4. 在“客户端配置”中选择 Codex、Claude Code、OpenCode、MiMoCode、OpenClaw 或 Hermes，复制对应配置。

复制配置到另一台电脑时，必须在目标电脑重新安装插件并重新生成 Base URL 和 Key。

## 8. 模型目录、项目提示词和 Agent HUD

### 8.1 模型目录

运行：

```text
FOMO FLOW: Model Catalog Toggle
FOMO FLOW: Model Catalog Status
```

该功能调整本机模型目录和可见模型列表，不等于 Provider 赠送额度，也不保证账号拥有某个模型的服务权限。遇到模型返回权限错误，应以 Provider 和 Devin 账号实际状态为准。

### 8.2 项目提示词

运行：

```text
FOMO FLOW: Project Prompt Settings
```

可按项目保存提示词并选择当前项目。注入后建议新建 Devin 对话，避免旧对话历史继续带着旧的系统上下文。

项目提示词只应放工作约定和编码规范，不要放密码、Cookie、API Key、私有证书或第三方访问令牌。

### 8.3 Agent HUD

运行：

```text
FOMO FLOW: Agent HUD
```

HUD 显示当前或最近会话的安全摘要，例如任务状态、Provider、模型、阶段、耗时、token 和缓存命中。它不会把原始提示词、完整工具输出或 API Key 展示在状态栏。

## 9. Codex 热路由和文件变更审阅

如果买家的 Devin Local 同时使用 Codex：

- 在配置面板中选择 Codex 当前 Provider、真实模型、协议和推理强度。
- 首次接管时可能需要让 Codex 重新加载配置；之后路由切换通常可以热生效。
- 插件只改本地路由字段，不负责 Codex 登录、账号认证或历史聊天存储。

文件变更审阅功能会捕获 Codex、Devin 或外部程序产生的文件变化，提供打开差异、接受和拒绝入口。拒绝操作会先检查文件是否被后续修改，避免用旧快照覆盖新代码。

## 10. 终端会话和工作区工具

命令面板提供：

```text
FOMO FLOW: Terminal Sessions · Execute
FOMO FLOW: Terminal Sessions · List
FOMO FLOW: Terminal Sessions · Close
```

终端会话用于长命令的执行、查询和关闭。它不替代 Devin 原生权限策略；执行高风险命令前仍应由用户确认。

FOMO FLOW 对本地搜索结果提供有限缓存，写入类工具不会按只读缓存处理。模型工具定义和工作区索引仍由 Devin 原生工作流负责。

## 11. 迁移到另一台电脑

### 11.1 只迁移插件

复制 `.vsix`，在新电脑安装并 Reload Window 即可。Provider、项目提示词和反代 Key 不会自动随 VSIX 迁移。

### 11.2 迁移配置

先关闭 Devin Local，再按需复制以下文件：

```text
~/.fomo-flow/配置.json
~/.fomo-flow/revproxy.json
~/.fomo-flow/protocol-bridges.json
~/.fomo-flow/project-prompts.json
```

这些文件可能包含密钥和项目路径，只能通过加密介质传输。恢复后重新打开 Devin，并在面板执行热重载和 Provider 探活。

更稳妥的方式是：在旧电脑导出不带密钥的配置包，在新电脑重新填写 API Key，再运行全链路测试。

## 12. 常见问题

### 安装成功但面板加载失败

1. Reload Window。
2. 运行 `FOMO FLOW: Self Check`。
3. 检查 FOMO FLOW 输出频道是否报端口占用。
4. 关闭其他旧版同类扩展后重启宿主。

### Provider 探活失败

检查 Base URL、Completion Path、Protocol、API Key、模型名和系统代理。Base URL 不要重复拼接 `/chat/completions` 或 `/messages`。

### Devin 仍然走官方模型

确认路由表里的 UID 是 Devin 实际发送的 UID，Provider 已启用，路由 `enabled` 没有被关闭，并且 `daoRoutes.enabled` 为 `true`。修改后点击热重载，再新建对话。

### 请求反复切换渠道

查看面板中的失败原因。401、403、404 和余额错误不会靠重复重试解决；先修正 Provider 配置。5xx、429 和网络错误会按熔断和探活策略恢复。

### 反代返回 `no_route`

反代只暴露已经配置路由的模型。先在模型路由中绑定 Provider/模型，再在模型反代面板勾选该模型对外开放。

### 反代返回 `protocol_not_enabled`

协议中转档案限制了目标协议。回到协议中转站，在档案中勾选需要的输出协议并保存同步。

### 升级后无法连接

运行：

```text
FOMO FLOW: Restore Direct Connection
```

重启 Devin Local，再重新开启 FOMO FLOW。这个命令用于清理本地锚定失败或旧端口残留，不会删除 Provider 配置。

### 忘记了本地反代 Key

在“模型反代”面板查看当前 Key，或使用重新生成 Key 功能。重新生成后，所有旧客户端都必须更新配置。

## 13. 安全边界

- API Key 只由买家自己填写；卖家交付包不包含额度和凭据。
- 默认本机监听不等于可以安全暴露公网。公网访问必须设置 Key，并限制模型范围。
- 不要把包含 `配置.json`、`revproxy.json`、Cloudflare 凭据或 Provider Token 的文件上传到公开网盘。
- 只从可信来源安装宿主和 Provider SDK，定期轮换长期 API Key。
- 对第三方 Provider 的计费、数据留存、内容政策和可用性，遵守对应服务条款。
- 任何“模型目录可见”状态都不能替代账号权限和 Provider 额度验证。

## 14. 一页验收清单

- [ ] Devin Local 已安装 VSIX 并 Reload Window。
- [ ] `FOMO FLOW: Self Check` 能看到本机控制面。
- [ ] 至少一个 Provider 探活成功。
- [ ] Devin 模型 UID 已绑定到真实上游模型。
- [ ] 新对话能正常返回文本或工具调用。
- [ ] 备用渠道和熔断策略按预期工作。
- [ ] 需要时再开启模型反代，并设置本地 Key。
- [ ] 需要时再创建协议中转档案并完成全协议测试。
- [ ] 迁移或导出前已确认文件中不含不应分享的密钥。
