# dao-proxy-pro 9.9.403

## 修复内容

### Grep 续跑不再重复步骤叙述

真实日志显示，本地 Grep 已经成功并返回完整结果，但第一次模型响应中尚未完成的步骤文字又被附加到第二次 Responses 请求。模型因此会重复“第 2 步尚未执行”、更改已经完成的步骤状态，或者在工具结果之后输出前后矛盾的说明。

现在仅在本地 `grep-only` 工具续跑时丢弃该轮临时助手文字和隐藏推理，只把原始对话、工具调用与真实 `function_call_output` 发送给上游。普通对话与 Devin 原生工具结果保持不变。

### 空 SSE 不再静默截断

部分 Responses 上游会返回 HTTP 200，但 SSE 中没有文本、推理、工具调用或有效完成事件。旧逻辑把这种空流当作成功结束，Devin 看起来就像回复突然停止。

现在空流会自动重试一次：

- 第二次产生有效内容时，正常交付完整回复。
- 第二次仍为空时，向 Devin 返回明确错误，而不是静默关闭响应。
- 重试只针对完全空的上游响应，不影响正常工具轮次与缓存前缀。

### Fast Context 保持 Devin 原生

`code_search/Fast Context` 没有被插件代理、禁用或改写，仍由 Devin 原生 LSP 执行。插件只在已有真实工作区根目录且搜索路径位于根目录内时接管 `grep_search/Grep/GrepSearch`。
