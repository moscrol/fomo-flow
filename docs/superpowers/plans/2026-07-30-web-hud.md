# Dao Web HUD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a loopback-only browser operations cockpit to Dao that exposes sanitized multi-session Agent state, route health, prompt-cache effectiveness, and recent request diagnostics at `http://127.0.0.1:8955/hud`.

**Architecture:** A pure projection module converts existing Agent Status, router status, and router usage facades into a bounded JSON snapshot. A shared-timer service coalesces snapshot updates and broadcasts them over SSE, while a small HTTP adapter serves loopback-only JSON/SSE/static routes from the existing Origin server. A dependency-free browser client renders the approved dark operations-cockpit layout and keeps only its selected session id in browser-local storage.

**Tech Stack:** Node.js CommonJS, built-in `http`, `crypto`, `fs`, and `path`; Server-Sent Events; plain HTML/CSS/JavaScript; Node `assert` tests.

---

## File map

- Create `core/web_hud_projection.js`: sanitize runtime inputs, hash session ids, aggregate cache/usage metrics, and return deterministic snapshots.
- Create `core/web_hud_service.js`: isolate reader failures, maintain one lazy shared timer, coalesce unchanged snapshots, and manage bounded SSE subscribers.
- Create `core/web_hud_http.js`: enforce loopback access and security headers, serve snapshot/SSE/static assets, and contain HTTP failures.
- Create `ui/web-hud.html`: semantic application shell with fixed element ids and no inline script.
- Create `ui/web-hud.css`: approved dark operations-cockpit layout, responsive narrow-screen layout, and accessible states.
- Create `ui/web-hud.js`: safe DOM rendering, SSE reconnect, polling fallback, session selection, and local pin restoration.
- Modify `vendor/bundled-origin/source.js`: lazily construct the HUD HTTP handler from existing router facades before the current control-plane dispatcher.
- Create `test/web-hud-projection.test.js`: projection, privacy, determinism, health, and cache math tests.
- Create `test/web-hud-service.test.js`: shared timer, coalescing, heartbeat, cleanup, client cap, and reader isolation tests.
- Create `test/web-hud-http.test.js`: route, security-header, loopback, JSON, SSE, and static-asset tests.

```js
const PUBLIC_LIMITS = Object.freeze({ sessions: 64, providers: 32, requests: 40 });

function sessionId(value) {

function hitRate(input, cached) {
  const i = finiteNonnegative(input);
```

```text
event: snapshot
```

`createWebHudHttpHandler({ service, assetDir, readFile })` returns a handler that returns `false` for non-HUD paths and `true` once it owns a HUD request. - [ ] **Step 4: Wire the adapter into Origin**

```js
{
  runtime: { healthy: Boolean(_eaRuntimeMod), mode: SP_MODE, port: _actualPort },
  agentSummaries: _eaRuntimeMod && _eaRuntimeMod.agentStatusList ? _eaRuntimeMod.agentStatusList() : [],
  routerStatus: _eaRuntimeMod && _eaRuntimeMod.routerStatus ? _eaRuntimeMod.routerStatus() : {},
  usage: _eaRuntimeMod && _eaRuntimeMod.routerUsage ? _eaRuntimeMod.routerUsage() : {},
}
```

Call `_ensureEaRuntimeMod()` and then the HUD handler near the start of `handleControl`, before global CORS is applied. Keep all failures inside the handler so model routing continues if HUD initialization fails.
