# Dao Flow 小白友好 UI 设计规格

- 日期：2026-08-09
- 目标平台：macOS Electron + React
- 设计决策：采用三大区域导航（运行中 / 配置 / 协作），观测台采用“结论优先”镜头。

## 目标

Dao Flow 的能力保持不变，但让第一次打开应用的人不需要理解 ACP、Provider、TTFT、P95、advisory 等术语就能完成三件事：

1. 判断当前服务是否正常。
2. 找到“添加渠道”“决定模型走哪家”“查看问题”等常用入口。
3. 在出现异常时看到影响、原因和下一步，而不是只看到原始数字。

## 非目标

- 不改变路由、预算、故障转移或 ACP 数据契约。
- 不删除旧 Dao Web 兼容入口。
- 不把诊断原始数据写入 renderer；技术细节继续来自现有脱敏接口。
- 不新增后端 endpoint 或自动控制动作。

## 信息架构

侧边栏从当前单层 14 项改为三组折叠/分组导航：

### 运行中

- **首页**（原“总览”）：现在是否正常、端口、渠道健康、请求概况。
- **实时情况**（原“实时 HUD”）：最近会话、请求、任务和实时告警。
- **问题与数据**（原“观测”）：结论优先的运行诊断，技术细节可展开。

### 配置

- **接入渠道**（原“渠道”）：添加 API、检查渠道是否可用、查看模型。
- **模型怎么走**（原“路由”）：把 Devin/Codex 模型连接到上游渠道。
- **本地接口**（原“模型反代”）：给客户端使用的本地 OpenAI/多协议端点。
- **远程访问**（原“内网穿透”）：隧道和公网端点。
- **接口兼容**（原“协议桥”）：不同协议之间的转接。
- **自定义模型**：多渠道模型和手动故障转移。
- **系统提示词**（原“本源”）：模式、经文和自定义注入；保留副标题说明原名“本源”。

### 协作

- **协作会话**（原“ACP 协作”）：ACP、Devin、Codex 会话谱系和活动。
- **任务进度**（原“任务”）：跨代理任务生命周期、尝试和交接。
- **Codex 连接**（原“Codex 热路由”）：显式切换 Codex 上游和思考强度。
- **外部接入**（原“连接器”）：Codex/IDE 的显式接入说明与交接信息。

每个导航项保留技术副标题和 `aria-label`，分组标题本身不承担操作。

## 首页

首页首屏以四个任务卡取代“看指标猜含义”：

- **现在正常吗？**：整体状态、端口、最近请求和需要处理的告警。
- **我要接入渠道**：进入接入渠道。
- **我要决定模型走哪家**：进入模型怎么走。
- **我要看任务和会话**：进入协作会话/任务进度。

所有卡片使用“结论 + 一句话解释 + 明确按钮”。技术字段放在“查看详情”之后。

## 观测台：结论优先

首屏固定回答四个问题：

1. **现在正常吗？** → `整体正常 / 有需要注意的地方 / 需要处理`。
2. **刚刚发生了什么？** → 请求总数、成功数、失败数和失败率，用自然语言解释。
3. **哪个渠道在工作？** → 渠道使用量、可用性、慢/失败状态。
4. **我要不要做什么？** → 只显示最高优先级的建议，提供“查看原因”或“去处理”入口。

现有数据映射为小白文案：

| 技术字段 | 默认显示 |
| --- | --- |
| TTFT / TTFT P95 | 首字响应速度 / 最慢的 5% 请求 |
| cache hit / miss | 复用成功 / 没复用上 |
| failureClass | 失败原因 |
| advisory rank/score | 建议顺序 / 参考分，不改变真实路由 |
| actual priority | 实际优先级 |
| channel strategy | 当前选路方式 |
| budget override | 本次请求是否因为预算临时改道 |

告警、失败模式、路由建议、配置历史继续分面板呈现，但面板标题改成结论式标题；每个面板提供“为什么”和“查看技术细节”的渐进展开。

## 交互与安全

- 所有写操作按钮使用动词：`添加渠道`、`保存并同步`、`手动置顶`、`回滚配置`。
- 状态颜色同时配合文字，不依赖颜色单独表达。
- 空态必须说明“为什么为空”和“下一步怎么做”。
- 保持现有 IPC allowlist、脱敏字段和只读观测边界。
- 路由 profile 仍只改变观测镜头；人工调整仍需显式保存。

## 验收标准

- 侧边栏只显示三组区域，14 个模块仍可达；快捷跳转继续可用。
- 现有每个 view 的 endpoint、写操作和权限行为不变。
- 首页能从一屏进入运行状态、接入渠道、模型路由和协作任务。
- 观测首屏不出现无解释的 `TTFT`、`P95`、`failureClass`、`advisoryScore` 裸字段。
- 观测异常至少显示“影响 + 原因摘要 + 下一步入口”，技术细节仍可展开。
- 补充导航分组测试、首页任务卡测试、观测文案/状态测试；Desktop typecheck、lint、test、build、Electron bundle 和 root smoke 全部通过。
