# Dao 路由观察与处理易用化设计

- 日期：2026-08-11
- 状态：用户已批准实施
- 原页面：`决策中心`
- 新页面名：`路由观察与处理`（侧栏简称 `路由观察`）

## 1. 问题

现有页面把“模型标识、使用场景、预算”表单放在首位，并称为“开始预演”。普通用户不知道模型标识从哪里找、为什么需要预演，也不容易从三列候选顺序和证据时间线得出“现在是否正常、是否需要处理、最近实际走了哪里”。

底层预演仍有工程价值：它在不调用 provider、不增加用量、不改变 priority 的前提下验证当前路由规则。但它不是日常必经步骤，不应成为页面主任务。

## 2. 方案比较

### A. 删除发送前检查

界面最简单，但失去在改路由或预算前验证结果的能力，也让已有的纯 planner 与安全端点没有用户入口。不采用。

### B. 结论优先，检查降级为可选工具（采用）

首屏先回答“要不要处理”和“最近实际走了哪里”；异常事项与真实证据成为主体。“发送前检查”放进默认折叠的可选区，所有参数来自现有配置的选择项，不要求手填。

### C. 自动持续预演

每次页面刷新或选择变化都自动 POST 预演。虽然没有 provider 副作用，但会产生不必要的计划关联和界面噪声，也容易被误解为自动改路由。不采用。

## 3. 页面信息架构

页面标题改为“路由观察与处理”，说明固定为：“看看最近请求实际走了哪里；只有出现异常时才需要处理。”

按以下顺序展示：

1. **现在要不要处理**：结论卡直接显示“目前正常”或“有 N 项需要处理”。有异常时按严重度展示原因、出现次数和直白动作；无异常时不显示空白技术表格。
2. **最近请求走了哪里**：以可选请求卡展示时间、最终模型/渠道和结果；选择后显示“规定顺序、实际尝试、跳过/回退原因、最终结果”的纵向事实。没有真实请求时说明“发起一次经由 Dao 的请求后这里会出现记录”。
3. **发送前检查（可选）**：默认折叠。说明“日常使用不需要；准备改路由或预算时再检查”。用户从下拉框选择已配置路由、常见用途和预算档位，再点击“查看预计路线”。

## 4. 选择项

### 模型

从现有只读 `GET /origin/ea/routes` 生成：

- value 使用已配置的 route UID；
- label 为 `route UID · provider / upstream model`；
- 去重、稳定排序、最多 100 项；
- 不允许 renderer 自由提交任意模型文本；无路由时禁用检查并提供“前往模型怎么走”。

### 用途

固定安全选项：

- 日常均衡（`balanced`，默认）；
- 写代码（`coding`）；
- 尽快回复（`fast`）；
- 控制成本（`cheap`）；
- 稳定优先（`reliable`）；
- 离线优先（`offline`）。

### 预算

固定档位：不设预算（默认）、`$0.01`、`$0.05`、`$0.20`、`$1.00`。预算档位仍使用 `strict`，不会自动选择 cheapest 或改变 priority。

## 5. 观测语义

预演结果不再把三列等权放在首位。先显示一句结论：

- 正常：`预计先走 <provider / model>，与规定优先级一致。`
- 有排除项：`有 N 个渠道本次不会尝试。`
- 预算阻止：`当前预算会阻止发送。`

详细候选顺序保留在结果展开区，仍明确区分“规定顺序”“预计尝试”“参考建议”；参考建议不改变真实顺序。

真实证据卡优先展示 outcome。fallback、skip、plan drift 等事件才显示醒目标记；普通 plan 事件使用中性样式。

## 6. 行为与边界

- 页面加载只 GET inbox、evidence、routes；不会自动 POST 预演。
- 只有用户展开可选区并点击按钮才发送现有 `route-preflight` 请求。
- ack/snooze 只改变本地收件箱状态，不改配置、不重试请求。
- 不新增 endpoint、IPC、远程能力或文件读取。
- 不自动切换 provider/model，不改变用户规定的 priority。
- 不展示 prompt、Authorization、完整路径或原始 session/job/request ID。

## 7. 测试策略

保留底层 planner、priority、无 provider 调用和安全边界测试，因为它们证明“检查不会偷偷改变真实路由”。UI 测试不再把手填表单当核心，而验证：

- 首屏结论和真实证据可读；
- 可选检查默认折叠且不会自动 POST；
- 模型、用途和预算均为选择项；
- 无已配置模型时禁用检查并提供路由入口；
- 选择后请求体仍只含白名单字段；
- 错误、轮询竞态、ack/snooze 和隐私边界保持正确。

## 8. 验收

- 小白打开页面无需填写即可知道当前是否正常、最近请求走了哪个模型和渠道。
- 不展开“发送前检查”也能完成日常观察和异常处理。
- 展开后无需键盘输入即可完成检查。
- 页面空态、异常态和真实数据态均有直白中文说明。
- Desktop focused/full tests、typecheck、lint、build、macOS 打包安装和真实 App 视觉验收通过。
