# Dao Flow HUD 实时任务桌设计

## 问题

实时 HUD 的“长任务运行情况”当前将所有已登记任务按 status 汇总。历史中的 `queued`、`failed` 与 `detached` 因而会被显示为“运行中 / 需要处理”，即使其心跳已经过去数小时。它既不表示实时工作，也不利于人工判断。

## 设计

HUD 展示层把 `freshnessMs <= 5 分钟` 作为实时任务门槛，与“当前工作”的生命周期一致。只对实时窗口内的任务计算“运行中 / 需要处理 / 已结束”并渲染任务卡；窗口外的任务只进入“已退役历史”计数，提示用户到“任务进度”查看。原始 HUD 快照和任务历史不修改。

会话目标为空时，安全投影显示“当前会话未上报目标”。这说明数据源确实没有目标字段，不把事实缺失误报为识别失败，也不从 prompt 或 IDE transcript 猜测标题。

## 边界与验收

- 五分钟整仍属于实时任务；超过五分钟的任意 status 都不在实时任务列表/实时统计中。
- 全部任务都过期时，面板显示“当前没有正在心跳的登记任务”和退役数量，不显示旧失败为待处理。
- 新鲜 `queued/running` 仍显示运行中；新鲜 `failed/timed_out/detached/transport_lost` 仍显示需要处理。
- 不新增 endpoint、IPC、任务写入、路由 priority 变更或远程能力。
- 任务 ID、prompt、Authorization、完整路径不进入 DOM。
