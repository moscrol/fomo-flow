# dao-proxy-pro 9.9.398 发布说明

本版本修复 `9.9.397` 已注册 ACP 工作区，但实际模型工具调用中的 `Assets` 仍可能原样进入 Devin 原生搜索执行器的问题。

## 根因

扩展日志确认当前窗口已加载新版本并注册 `e:\新增运行时状态机`，但路由工具调用没有产生路径修正记录。仅依赖扩展宿主环境不足以保证每个请求都获得对应窗口和会话的工作区根。

## 修复

- 从当前请求的官方 `<workspace_information>` 提取工作区根。
- 同时识别项目提示词中的 `项目根目录`、`工作区目录`、`Workspace root` 与 `Working directory`。
- 提取结果必须是本机真实存在的目录，避免提示词普通文本被误识别。
- 工作区根作为当前请求上下文直接传到流式、非流式和内部工具续跑路径。
- ACP 环境、多根工作区消歧、最近搜索目录仍作为并行来源保留。
- Devin 原生搜索执行器与工具 Schema 不变。

## 实机验证

使用当前 `custom-sp.json` 中的真实项目提示词提取到：

```text
E:\新增运行时状态机
```

本次失败参数得到：

```text
Assets -> E:\新增运行时状态机\Assets
```

路径修复、工具契约、工作区策略、缓存与 307 项全链路测试全部通过。
